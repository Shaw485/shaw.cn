Read-only diagnostics

Agent 自检与工具

先验证工具能力，再运行开发诊断、规划实验，并由人逐项完成诊断 Oracle；五项操作都不会审批、激活或修改搜索策略。

5 个受控工具
Tool 01

Agent Eval 自检

运行固定 12 项任务，检查工具选择、证据绑定、恢复、预算和离线 Replay。

等待运行

运行后只显示成绩单摘要，不显示任务 Trace 或工具响应正文。

Tool 02

Query 构造器

从固定 smoke 来源生成确定性变体，用于扩充待观察的 Bad Case，不继承相关性标签。

等待运行

运行后只显示 Query 集 ID 和数量边界，不显示任何原始 Query。

Tool 03

Bad Case 诊断执行器

在全量商品基线中运行固定 59 条开发 Query，比较原始 Query 与受控变体的结果数量及 Top 10 稳定性，找出需要人工判断的诊断候选。

等待运行

运行后展示执行 ID、Query 集、分类计数以及最多 12 个可理解样本；开发诊断不等于正式搜索质量评测。

Tool 04

诊断驱动实验规划器

读取刚生成的不可变 Bad Case 证据，自主选择一个受控、可证伪的候选策略，并明确行为证据与质量证据的边界。

等待诊断证据

诊断完成后，Agent 会展示选中的策略、触发证据、实验双轨和失败条件；本工具不会修改线上策略。

Tool 05

Human Diagnostic Oracle

把 40 个诊断候选按 20 个来源簇逐项交给站长判断。先完成 30 项 Query 意图判断，再查看结果完成 40 项行为判断。

Analysis → Experiments → Gate

Agent 为什么提出这个策略

先归纳失败模式，再逐个运行候选策略；平均分更高但回归过大的方案会被门禁淘汰。

确定性规则
01
Root-cause analysis

根因诊断

运行后展示本轮覆盖的 Query 数及各类失败信号。

02
Bounded strategy search

候选实验

运行后用中文展示每个候选的适用问题、机制、参数、三项指标、风险及淘汰原因。

03
Release guardrails

发布门禁

只有全部门禁通过的候选，才会进入待审批提案。

当前门禁是 smoke 阶段的工程默认值，尚不代表生产发布政策；正式阈值仍需站长决策并在更大评测集验证。
