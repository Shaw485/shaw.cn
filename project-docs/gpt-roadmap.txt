# Create GPT Step by Step

## 项目目标

使用 Python 和 PyTorch，从零实现一个可以训练和生成文本的迷你 GPT。

项目首先聚焦 GPT 的核心原理，不追求 ChatGPT 级别的参数规模。完成基础模型后，再逐步加入 BPE tokenizer、指令微调和聊天能力。

## 学习原则

- 每次只实现一个核心概念
- 先理解原理，再编写代码
- 不直接复制完整 GPT 实现
- 每个阶段都必须有可验证的结果
- 每完成一个阶段，都在 `RECORD.md` 中记录
- 只把公开安全的代码、配置和脱敏聚合材料提交到 GitHub；受限数据、权重和可还原文本保持私有

## 实验与视频素材留档原则

- 每次模型、数据、训练目标或生成策略发生实质优化后建立独立里程碑。
- 每个里程碑保存配置、checkpoint、指标、固定样本、曲线、结论和文件校验值。
- 预训练、SFT、BPE 等阶段使用不同文件名前缀，禁止覆盖上一阶段材料。
- 所有阶段使用固定评测问题，为项目视频提供可直接比较的前后结果。
- 视频素材入口统一维护在 `VIDEO_MATERIALS.md`。

## 技术栈

- Python 3
- PyTorch
- Git 和 GitHub
- Markdown
- 小型文本训练数据集

## Roadmap

### 1.0 项目初始化

任务：

- 创建本地项目目录
- 创建公开 GitHub 仓库
- 创建 `ROADMAP.md`
- 创建 `RECORD.md`
- 检查 Python 和 PyTorch 环境

完成标准：

- GitHub 仓库可以公开访问
- 两份 Markdown 文档已经上传
- Python 和 PyTorch 可以正常运行

### 1.1 字符级 Tokenizer

任务：

- 读取训练文本
- 找出全部字符
- 创建字符到整数的映射
- 实现 `encode`
- 实现 `decode`

完成标准：

```python
decode(encode(text)) == text
```

### 1.2 构造训练数据

任务：

- 把文本转换为 token 序列
- 划分训练集和验证集
- 理解 context window
- 构造输入 `x` 和目标 `y`
- 实现 batch 采样

完成标准：

- 能打印一个 batch
- 能解释输入和目标为什么错开一个 token

### 2.0 Bigram 基线模型

任务：

- 创建 token embedding
- 根据当前 token 预测下一个 token
- 计算交叉熵损失
- 完成第一次训练
- 生成第一段文本

完成标准：

- 训练损失明显下降
- 模型可以连续生成 token

### 3.0 Self-Attention

任务：

- 理解 Query、Key 和 Value
- 手动实现单头注意力
- 添加 causal mask
- 实现缩放点积注意力
- 实现多头注意力

完成标准：

- 张量形状全部正确
- 每个位置不能看到未来 token
- 能解释注意力权重的含义

### 4.0 Transformer Block

任务：

- 实现 LayerNorm
- 实现前馈神经网络
- 添加残差连接
- 组合多头注意力和前馈网络
- 堆叠多个 Transformer Block

完成标准：

- 一个 batch 可以正常前向传播
- 梯度可以正常反向传播

### 5.0 GPT 模型

任务：

- 添加 token embedding
- 添加 position embedding
- 堆叠 Transformer Block
- 添加最终 LayerNorm
- 添加语言模型输出层
- 实现 loss 计算

完成标准：

- 输入 token 后可以输出 logits
- 提供目标 token 时可以输出 loss
- 可以统计模型参数量

### 6.0 训练 GPT

开始正式训练前，先完成训练语料准备：

- 备份并隔离原始语料
- 清除异常控制字符并统一换行
- 识别下载站声明、广告和重复章节标题
- 生成清洗报告并抽样核对正文
- 剔除高置信重复章节版本，生成 stage3 训练底稿
- 对 stage3 重新做内容污染与重复块复查
- 将清洗语料重新编码并划分训练集和验证集

任务：

- 编写训练循环
- 使用 AdamW 优化器
- 定期计算训练集和验证集损失
- 保存模型 checkpoint
- 支持重新加载模型

### 6.1 继续进入训练前编码

- 将 `doupo_stage3.txt` 输入 tokenizer，重新统计字符表与 token 序列
- 用 90%/10% 重切训练/验证集
- 在 6.0 的基础上进行第一次完整训练循环

当前进展：

- 已使用 `train_gpt_stage3.py` 在 `doupo_stage3_tensors.pt` 上跑通 80 步 smoke test，验证训练与验证 loss 均下降。
- 训练脚本已支持续训（`RESUME_TRAINING`）与采样生成（`GEN_STEPS`、`GEN_START_TEXT`、`TOP_K`、`TEMPERATURE`）。

完成标准：

- 训练损失和验证损失整体下降
- 保存后的模型可以重新加载
- 加载后可以继续训练或生成文本

### 6.2 Embedding 与输入表示

- 使用 `token_embedding` 将 `B x T` token ids 映射到 `B x T x D` 的向量
- 使用 `position_embedding` 将位置 `0..T-1` 映射到 `T x D` 的位置向量
- 两者逐位相加得到 Transformer 可消费的 `contextual_x`
- 完成本步形状检查并用于后续 `attention` 输入

### 6.3 v4 正式语料与本机 800 万参数预训练

状态：已完成。路线已由云端 A10 优先调整为本机 Apple M4 优先，云端方案保留为备选。

依赖顺序：

1. 审核 113 组章节版本并冻结决策
2. 修复可证实的异常章节标题，核对缺失编号
3. 按完整章节组切分 train/val/test，禁止同章版本跨集合
4. 仅使用 train 文本统计学习 2000 条 BPE 合并规则
5. 每章编码结束后插入一个 `<EOS>`，生成三个 Token 张量
6. 在 M4 16GB 上完成训练、恢复和检查点冒烟测试
7. 从随机权重训练约 810 万参数 GPT，并保存固定 10 题样本

冻结结构：Embedding 256、8 层、8 头、FFN 1024、Context 512、Micro Batch 2、梯度累积 4。首阶段训练 3000 步；随后从 Step 2600 验证最优权重以更低学习率续训到累计 6000 步。完成标准是 train/val/test 全部可复现、EOS 数量与章节数一致、Loss 有限且整体下降、最佳与最新 checkpoint 均可复载，并用多指标 Harness 阻止只追求 Loss。

完成结果：正式语料共 6,120,275 字符，按章节组切为 1599/92/84 个章节段；三个 BPE 张量逐字还原通过，EOS 数量与章节段数完全一致。8105025 参数模型在 Apple M4/MPS 上累计训练 6000 步，验证 Loss 最低 4.7759（Step 6000），所选最佳模型独立 Test Loss 为 4.7476。发布候选的五个固定小说提示词因出现连续 12 个“试”而被自动门槛标记为 `REVIEW`，人工抽样也发现语法与语义混乱，因此只判定“Loss 改善”，不判定“综合能力改善”。首阶段归档至 M006，续训和 Harness 归档至 M007。

### 6.6 1488万模型的正式SFT数据重构

状态：M017准入审查已完成，现有v5.2.2判定为Needs revision。结构和BPE兼容通过，但语义审核、模板多样性、split独立性、多轮、长上下文和回答长度不满足正式训练门槛。

下一阶段先构造v6冻结数据，不直接训练：隔离19条P0、退出243条机械verification wrapper、重审2340条教师数据、去除995条元证据包装，并按10000条中心方案补齐任务维度。新数据通过证据/语义/重复/Token/封存测试门后，才从M016 Step 5750开始20步SFT安全试跑。

依赖顺序：

1. 冻结 M007 Step 6000 最佳预训练 checkpoint
2. 使用 v4 BPE 与聊天特殊 Token 重新编码 SFT 数据
3. 审核训练/验证/测试主题隔离、证据和答案质量
4. 保存同一固定 10 题的 SFT 前基线
5. 先做 20 步安全试跑，再从同一预训练点开始正式 SFT
6. 用验证集选模型，最后一次性评估测试集并与 M006 对比

当前进度：完整数据仍为3000条v4候选，2400/300/300切分、7类配额、BPE兼容、2999条证据定位和零泄漏保持通过。章节定位器只认分隔符确认的正式v4标题，累计重绑定262条旧章节号。进一步发现字面索引会把“云山”误命中为“高耸入云山峰”，因此不再用字面命中替代语义事实；共1067条“首次、先后、最多、主角、全书未说明”等任务被改成当前证据可直接核验的问题。全局断言扫描由172条降为0条。经用户授权，Codex AI已完成600/600评估记录审核：521条通过、79条修改后通过、0条拒绝；审核决定已合并成AI冻结副本，并生成2999条training-ready SFT候选。AI审核不冒充独立真人签字，正式发布仍需独立真人治理决定。

已完成v4 SFT张量编码和20步安全试跑，验证Loss从7.5522降至5.0587；随后执行500步正式小跑，验证Loss从6.7152降至1.5823，最佳验证Loss为step 400的1.3442。固定10题显示模型已经开始学会短答和EOS停止，但人物、章节标题和局部证据判断仍会答错，因此只判定“格式能力建立”，不判定“问答质量达标”。

针对M010非小说问题仍输出章节号和数字模板的问题，M011新增3000条通用聊天、基础算术、项目解释、实时能力边界、学习计划、指令改写、诚实未知和领域切换样本，与2999条小说SFT合并为5999条混合SFT数据。2000步后验证Loss降至1.6600，天气、未知实体和学习鼓励类样本开始有聊天形态；继续训练到5000步后，100个验证batch复核显示step5000验证Loss为0.9791，低于step3500的1.1292。但样本仍显示数学、人物介绍和证据判断不达标，并出现对萧炎、药尘、异火的过度拒答。下一步应先建立分类型SFT评估集，并补强高质量通用聊天、基础推理和小说人物数据，再从同一预训练checkpoint重新SFT。

M011分类型评估集已建立，30题公开诊断不消耗隐藏测试集。step5000 latest在低温采样下总分5/30，EOS 29/30；小说人物、小说事实和基础数学均为0/5，证据判断和能力边界各1/5，通用聊天3/5。当前路线因此调整为：先按失败类别构造v5补强SFT数据，特别是已知小说实体必须回答、证据片段实体匹配、基础算术和不同实时问题边界，再重新训练并用同一分类型评估验收。

M012已完成v5补强数据准备：在5999条M011数据基础上新增2000条定向样本，形成7999条SFT数据和可训练张量，并完成100步安全试训。验证Loss从6.3811降到5.1405，但30题诊断仍为5/30，说明100步只验证链路，不代表能力修复完成。下一步进入v5正式SFT：先跑2000步，再用30题分类诊断和固定小说/非小说样本判断是否继续训练或继续补数据。

v5正式SFT已跑到2000步，验证Loss降到1.6750，但收紧评估规则后的30题诊断只有6/30。当前判断是“数据方向略有帮助，但模板污染明显”：数学仍为0/5，通用聊天会输出“不要回答章节号”类训练痕迹，证据判断仍复制错误实体。下一步优先修v5数据，而不是直接把同一数据继续冲到5000步。

M013已完成v5.1去数学与污染修复：从M011的5999条数据中移除基础算术、数学话题、领域切换、续写/复述元任务、“别提小说章节”前缀及冻结评估提示重合项，再加入361条按语义组隔离的修复样本，形成4676条SFT数据（3629/520/527）。审计确认数学记录0、冻结评估完整提示及其子串包装重合0、修复样本语义组跨split泄漏0。

新的v2严格评估用“指令遵循”替换数学类别，并固定CPU、greedy和EOS门槛。M012 step2000在该口径下为4/30；M013重新从M007训练2000步后，验证Loss由6.8401降至3.2569、最佳为2.7157，评估为4/30、EOS 29/30。继续追加3000步形成累计5000步后，最佳抽样验证Loss为1.0625；latest评估为7/30、EOS 25/30，小说事实与证据判断各2/5、通用聊天3/5，但小说人物、能力边界和指令遵循仍为0/5。评估入口现已强制核对checkpoint与张量的数据摘要；当前路线停止盲目加step，下一轮只针对失败类别做小规模可归因数据实验。

### 6.6 Stage A分词器与模型容量实测

状态：已完成。测试集封存条件下，3000 merges在1000/2000/3000三组BPE中取得最低验证BPC；固定该分词器后，420万、836万、1488万参数模型各训练1000步，最佳验证BPC分别为5.4969、5.3820、5.3239。

当前采用双分支：1488万参数是最大质量正式训练候选，836万参数用于高频本机迭代。1488万只比836万改善约1.08%且训练慢约70%，所以不把参数增长本身当作主要优化手段。下一步从随机权重正式预训练1488万模型6000步，并用验证BPC、重复率、Distinct-2/3、EOS、固定续写和人工抽查共同早停；之后必须重新SFT。详见`reports/milestones/015_scaling_stage_a/README.md`和`docs/adr/0002-stage-a-scaling-result.md`。
