极简数学题闹钟 App PRD
1. 项目概述
模块  内容
产品定位与背景  极简数学题闹钟 App 是一款单闹钟、极简设置、强约束关闭的工具型 App,核心
目标是让用户设置一个更难被无意识关闭的闹钟。传统闹钟通常默认“关闭动作=
成功唤醒”,但真实场景里,用户可能在半睡眠状态下误关闹钟后继续入睡,因
此需要通过答题机制提高关闭门槛。
核心特点  仅支持一个闹钟;首页即设置页;响铃后必须答题才能关闭。
产品目标  减少无意识关闭闹钟的概率;提高“关闭闹钟”与“真正醒来”的一致性。
目标用户  面向经常无意识关闭闹钟、希望保证顺利起床的用户。
1.5 目标平台与技术栈
项  说明
目标平台  Android(本期仅面向安卓,不含 iOS)。建议最低支持 Android 8.0(API 26),目标
API 34。
技术栈建议  原生 Android,Kotlin + Jetpack Compose(或 XML 布局);闹钟调度使用
AlarmManager;本地状态持久化使用 DataStore / SharedPreferences;铃声播放使
用 MediaPlayer / RingtoneManager。允许 vibe coding 自行选择等价实现。
数据存储  单闹钟为唯一状态,采用本地键值存储(DataStore / SharedPreferences)。无需数
据库、无需服务端、无账号体系。
时间格式  统一使用 24 小时制(如 09:32)。
国际化  本期仅中文,暂不做多语言。
2. 产品设计原则

===== 第 2 页 / 共 25 页 =====
原则/要求  说明
极简优先  只保留完成核心目标所需的最少功能,不引入与单闹钟主任务无关的复杂配
置。
单任务优先  只解决“设置一个闹钟,并让它更不容易被无意识关闭”这一问题。
首页即设置页  不采用传统闹钟列表结构,所有关键信息尽量集中在首页完成。
状态优先  首页优先展示当前主状态与剩余时间,帮助用户快速理解闹钟是否正在生效。
UI 风格  整体风格应简洁克制,接近系统工具型产品;核心信息正常高亮,避免引入与
系统工具气质不一致的夸张视觉表现。
交互要求  设置主路径尽量压缩为“选时间 → 确认”;不同状态下按钮、状态文案、提示
文案必须一致且无歧义;闹钟时间模块采用滚轮式时间选择器,仅展示 3 行(中间
行为当前选中项、上下各 1 行为相邻时间);小时列 00‒23 循环、分钟列 00‒59
循环,滚轮首尾相连(infinite loop),形成循环选择体验;当前选中时间保持高亮与
完整不透明显示,其上方和下方相邻的未选中时间项以 70% 透明度展示,用于弱
化非焦点信息并突出当前选择。
3. 产品范围与核心规则
分类  内容
本期范围  单闹钟设置、修改、失效、查看题目、响铃答题关闭、首页状态展示、权限风
险提示。
暂不纳入本期  多闹钟管理、重复提醒、复杂日期规则、自定义题库、社交分享、统计分析。
核心规则  仅支持一个闹钟;响铃后必须答题才能关闭;响铃前可主动失效;失效状态停留 3
秒后自动回流;提醒权限未开启不作为主状态,而作为叠加态 / 风险态展示。闹钟
为一次性语义:本次响铃被消费后(无论答对关闭还是达到 10 分钟兜底超时自动
停止),该闹钟即失效,系统不会自动重排下一次,需用户重新设置;本期不支持重
复/每日闹钟。
权限与系统能力需求  需要系统通知/提醒权限;需验证前后台、锁屏、静音等场景下提醒触达与答题
关闭链路是否可用;需定义权限未开启时的风险提示文案。

5.12 数学题规则(核心答题机制)
本节定义"答题关闭闹钟"的核心逻辑,是本 App 的核心功能,研发必须严格按此实现。
项  规则
题型  题目固定形式为  a*b+c*d (两个乘积之和),其中 a、b、c、d 均为 1‒9 的整数。
数值范围  a、b、c、d 各自在 1‒9 范围内独立随机取值;结果 = a×b + c×d,取值范围为 2‒
162,恒为正整数。
运算结构  固定 2 次乘法 + 1 次加法;需先算乘后算加(遵循先乘除后加减的运算优先级)。
每次题量  响铃时需连续答对 1 题 即可关闭闹钟(MVP 取 1 题;如需提高门槛可后续扩展为 N 题,
本期不实现)。
答题交互  数字键盘手动输入答案 + "确认"按钮提交。不采用选择题。
答对处理  停止铃声 → 销毁本次闹钟任务 → 首页状态恢复为"未设置"。
答错处理  提示"答案错误,请重试",不限制答错次数,铃声持续播放;答错后重新生成一道新题,防
止用户蒙对同一题。
题目生成时机  响铃触发时实时随机生成;每次答错后重新随机生成。
"查看题目"与响铃题一 M03 查看题目入口展示的是同规则的示例题(随机生成,仅供预览理解机制),与响铃时
致性  真正要答的题规则一致但题目独立;弹层内"换一题"按同规则重新随机生成一道示例
题。
答案输入边界  输入框最多 3 位数字(结果最大 162);提供删除/清空键;答案为空时确认按钮置灰不可
提交;仅接受非负整数,不含小数点与负号。
答对/答错时序 答对:先停止铃声,再执行关闭动画/跳转,避免关闭后仍有残留声音;答错:铃声不中断,
输入框清空并即时刷新为新题,给出答案错误,请重试轻提示。
5.13 响铃技术方案(Android 强约束闹钟)
💡 可行性关键:"必须答题才能关闭"要求 App 在设定时间(含锁屏 / 后台 / 熄屏)能可靠拉起全屏
答题页并持续响铃。这是本 App 成立的技术前提,研发须优先验证。

===== 第 16 页 / 共 25 页 =====
项  方案
定时调度  使用  AlarmManager.setAlarmClock() (闹钟类专用 API,可在 Doze 模式下精
确触发,系统会给予最高优先级),而非 setExact / setAndAllowWhileIdle。
触发后拉起页面  AlarmManager 触发 → 发送高优先级 全屏通知(full-screen
intent,category=CATEGORY_ALARM) → 拉起响铃答题 Activity;答题 Activity
需设置  setShowWhenLocked(true)  与  setTurnScreenOn(true) ,以便锁
屏 / 熄屏状态下点亮屏幕并置于锁屏之上。
持续响铃  响铃期间启动前台服务(Foreground Service)持有 MediaPlayer 循环播放,保证进
程不被回收、铃声不中断,直到答对后由前台服务停止。
强约束关闭  响铃答题 Activity 屏蔽返回键 / Home 键的直接退出通道,唯一关闭出口是答对数
学题;通知不提供"清除 / 划掉即关闭"的捷径。
静音 / 勿扰  使用  AudioManager.STREAM_ALARM  闹钟音频流,该流不受媒体音量与勿扰(部
分策略)影响,系统静音键也通常不静默闹钟流,确保静音场景下仍能出声。
必需权限  USE_FULL_SCREEN_INTENT (Android 14+ 需运行时授予)、
SCHEDULE_EXACT_ALARM  /  USE_EXACT_ALARM (Android 12+ 精确闹钟)、
POST_NOTIFICATIONS (Android 13+ 通知权限)、前台服务权限。
厂商保活风险  部分国产 ROM(MIUI / EMUI / ColorOS 等)对后台自启与保活限制严格,可能影响精
确触达。研发需在目标机型上验证,并在权限风险提示中引导用户开启"自启动 / 后
台运行 / 忽略电池优化"。
